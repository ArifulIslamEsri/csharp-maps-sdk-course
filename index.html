01

Variables & Data Types

~45 min
Real-world analogy: Think of variables as labeled boxes. The box has a name (the variable name), a size/type (what kind of data it can hold), and contents (the value). A box labeled age can hold a number, while a box labeled username holds text.

🧠 What is a variable?

A variable is a named storage location in memory that holds a value. In C#, every variable must have a declared type — this tells the compiler exactly how much memory to allocate and what operations are valid on that data.

Variables in C# follow this pattern: type name = value;

C# variables_basics.cs 
// ── DECLARING VARIABLES ──────────────────────────────────────

// Explicit type declaration
int age = 25;
string name = "Alice";
double latitude = 34.0522;   // Los Angeles latitude
bool isMapLoaded = false;

// 'var' lets the compiler infer the type (same result at runtime)
var city = "Los Angeles";   // compiler infers: string
var zoom = 12;               // compiler infers: int

// ── CONSTANTS (value can never change) ───────────────────────
const double EarthRadiusKm = 6371.0;
const string AppVersion = "1.0.0";

// ── STRING OPERATIONS ─────────────────────────────────────────
string firstName = "Jane";
string lastName = "Doe";
string fullName = firstName + " " + lastName;  // concatenation

// String interpolation (recommended — cleaner syntax)
string greeting = $"Hello, {firstName}! You are {age} years old.";
string coords = $"Lat: {latitude:F4}, Lon: {-118.2437:F4}";  // :F4 = 4 decimal places

// Useful string methods
int len = fullName.Length;                     // 8
string upper = fullName.ToUpper();             // "JANE DOE"
bool starts = fullName.StartsWith("Jane");    // true
string trimmed = "  hello  ".Trim();           // "hello"

// ── NULLABLE TYPES ────────────────────────────────────────────
// Value types (int, double, bool) cannot be null by default.
// Add '?' to make them nullable.
int? optionalZoom = null;   // no zoom set yet
string? optionalUser = null;  // user might not be logged in

// Null-coalescing operator (??) — provide a default if null
int zoomLevel = optionalZoom ?? 10;   // uses 10 if null

// ── TYPE CONVERSION ───────────────────────────────────────────
string numberText = "42";
int parsed = int.Parse(numberText);        // throws if not a number!

bool success = int.TryParse(numberText, out int result);
// TryParse is SAFE — returns false instead of crashing

double d = (double)42;     // explicit cast: int → double
string s = age.ToString();  // any type → string
C# arrays_and_collections.cs 
// ── ARRAYS — fixed size, same type ───────────────────────────
int[] zoomLevels = { 1, 5, 10, 15, 20 };
string[] platforms = new string[3];   // creates array of 3 empty slots
platforms[0] = "Windows";
platforms[1] = "Android";
platforms[2] = "iOS";

int count = platforms.Length;  // 3 — always use Length for arrays

// ── LIST — dynamic size, same type ───────────────────────────
List<string> layers = new List<string>();
layers.Add("FeatureLayer");
layers.Add("RasterLayer");
layers.Add("GraphicsLayer");
layers.Remove("RasterLayer");     // removes by value
int layerCount = layers.Count;     // use .Count for lists

// ── DICTIONARY — key/value pairs ─────────────────────────────
Dictionary<string, double> cityLatitudes = new()
{
    { "Los Angeles", 34.0522 },
    { "New York",   40.7128 },
    { "Chicago",    41.8781 }
};

double lat = cityLatitudes["New York"];  // 40.7128
cityLatitudes["Seattle"] = 47.6062;       // add or update

// Safe lookup — TryGetValue won't crash if key missing
if (cityLatitudes.TryGetValue("Miami", out double miamiLat))
    Console.WriteLine($"Miami lat: {miamiLat}");

⚠️ Common Mistakes

Using int when you need double for GPS coordinates: int lat = 34; → loses all decimal precision
double lat = 34.0522; → correct
Forgetting arrays are 0-indexed: platforms[3] → IndexOutOfRangeException (only indexes 0,1,2 exist!)
platforms[2] → correct for 3rd element
Using int.Parse() on unknown input (crashes!): int.Parse(userInput) → throws FormatException
int.TryParse(userInput, out int val) → safe
🗺️ Maps SDK Connection

The Maps SDK constantly uses these types: double for latitude/longitude coordinates, List<Layer> to manage map layers, Dictionary<string, object> for feature attributes, bool for flags like isVisible, and string for layer IDs and service URLs.

02

If-Else Statements & Decision Making

~40 min
Real-world analogy: A GPS app making decisions: "If the user is within 200m of the destination → show arrival message. Else if they took a wrong turn → recalculate. Else → continue guiding." That's exactly if-else logic.

🧠 What is a conditional statement?

Conditionals control the flow of execution — your program makes choices based on conditions. Without them, code always runs the same path every time. C# uses if, else if, else, and switch for branching logic.

C#conditionals.cs
// ── BASIC IF/ELSE IF/ELSE ─────────────────────────────────────
int zoom = 15;

if (zoom >= 18)
{
    Console.WriteLine("Street-level view — show building outlines");
}
else if (zoom >= 10)
{
    Console.WriteLine("City view — show neighborhoods");
}
else if (zoom >= 5)
{
    Console.WriteLine("Regional view — show cities");
}
else
{
    Console.WriteLine("Global view — show countries");
}
// Output: "City view — show neighborhoods"

// ── COMPARISON OPERATORS ──────────────────────────────────────
//  ==  equal to              !=  not equal to
//  >   greater than          >=  greater than or equal
//  <   less than             <=  less than or equal

// ── LOGICAL OPERATORS ─────────────────────────────────────────
bool isLoggedIn = true;
bool hasApiKey = true;
bool isOffline = false;

if (isLoggedIn && hasApiKey)    // AND — both must be true
    Console.WriteLine("Access granted");

if (isOffline || !hasApiKey)    // OR — at least one true; ! = NOT
    Console.WriteLine("Cannot load map");

// ── SWITCH STATEMENT ──────────────────────────────────────────
// Better than many else-if when checking one variable
string platform = "Android";

switch (platform)
{
    case "Windows":
        Console.WriteLine("Use WPF or WinUI framework");
        break;
    case "Android":
    case "iOS":                              // fall-through — same code for both
        Console.WriteLine("Use MAUI framework");
        break;
    default:
        Console.WriteLine("Unknown platform");
        break;
}

// ── SWITCH EXPRESSION (modern C# — cleaner) ───────────────────
string framework = platform switch
{
    "Windows"          => "WPF or WinUI",
    "Android" or "iOS" => "MAUI",
    _                  => "Unknown"   // _ = default
};

// ── TERNARY OPERATOR — compact one-line if/else ───────────────
string status = isLoggedIn ? "Welcome back!" : "Please log in";
//              condition  ?  if true           : if false

// ── NULL-CONDITIONAL OPERATOR ?. ──────────────────────────────
// Safely access members that might be null
string? layerName = null;
int? nameLength = layerName?.Length;  // null if layerName is null, no crash!
string safe = layerName ?? "unnamed";   // "unnamed" as fallback
💡 Important: In C#, == compares values for primitive types. For strings, == also compares content (not memory address), which is different from Java. So "hello" == "hello" is always true.

⚠️ Common Mistakes

Using assignment = instead of comparison ==: if (zoom = 10) → won't compile (good!), but easy mental slip
if (zoom == 10) → correct
Forgetting break in switch statements: case "A": DoSomething(); // missing break! → compile error in C# (unlike C)
case "A": DoSomething(); break; → correct
Null reference crash with string comparison: if (layerName == null && layerName.Length > 0) → NullReferenceException!
if (layerName != null && layerName.Length > 0) → check null first
🗺️ Maps SDK Connection

In Maps SDK you'll constantly write conditionals like: checking if a layer is visible before querying it, deciding which renderer to apply based on data type, checking if the user is authenticated before loading secured services, and switching behavior based on the target platform (WPF vs MAUI vs WinUI).

03

Loops — for, while, foreach, do-while

~45 min
Real-world analogy: Imagine drawing 100 map pins one by one — instead of writing 100 lines of code, you write the pin-drawing code once and tell the program to repeat it for each location in your list. That's a loop.

🧠 The four loop types in C#

  • for — when you know exactly how many times to repeat
  • while — repeat while a condition is true (count unknown)
  • do-while — like while, but always runs at least once
  • foreach — iterate over every item in a collection (most common)
C#loops.cs
// ── FOR LOOP — count-controlled ───────────────────────────────
// Structure: for (initializer; condition; iterator)
for (int i = 0; i < 5; i++)
{
    Console.WriteLine($"Zoom level: {i}");  // runs 5 times: 0,1,2,3,4
}

// Looping over an array with index access
string[] platforms = { "WPF", "MAUI", "WinUI" };
for (int i = 0; i < platforms.Length; i++)
{
    Console.WriteLine($"[{i}] {platforms[i]}");
}

// ── FOREACH LOOP — collection iteration (preferred) ───────────
// Cleaner when you don't need the index
List<string> layers = new() { "Roads", "Buildings", "Parks" };

foreach (string layer in layers)
{
    Console.WriteLine($"Loading layer: {layer}");
}

// Foreach over a dictionary
Dictionary<string, int> featureCounts = new()
{
    { "Rivers", 42 }, { "Parks", 17 }, { "Roads", 1204 }
};

foreach (var (name, count) in featureCounts)
{
    Console.WriteLine($"{name}: {count} features");
}

// ── WHILE LOOP — condition-controlled ─────────────────────────
int retries = 0;
bool mapLoaded = false;

while (!mapLoaded && retries < 3)
{
    // Try to load the map
    mapLoaded = TryLoadMap();
    retries++;
    Console.WriteLine($"Attempt {retries}...");
}

// ── DO-WHILE LOOP — runs at least once ────────────────────────
do
{
    Console.WriteLine("Enter a valid zoom level (1-20):");
    int.TryParse(Console.ReadLine(), out zoom);
} while (zoom < 1 || zoom > 20);

// ── BREAK & CONTINUE ─────────────────────────────────────────
foreach (string layer in layers)
{
    if (layer == "Roads") continue;   // skip Roads, go to next iteration
    if (layer == "Parks") break;     // stop loop entirely at Parks
    Console.WriteLine(layer);
}

// ── LINQ — functional-style loops (very common in .NET) ───────
var visibleLayers = layers.Where(l => l.StartsWith("R")).ToList();
// Result: ["Rivers", "Roads"]

var upperLayers = layers.Select(l => l.ToUpper()).ToList();
// Result: ["RIVERS", "PARKS", "ROADS"]

int totalFeatures = featureCounts.Values.Sum();  // 1263

⚠️ Common Mistakes

Infinite loop — condition never becomes false: while (true) { /* no break! */ } → freezes the app
while (retries < 3) { retries++; } → always increments toward end
Off-by-one error (very common!): for (int i = 0; i <= array.Length; i++) → crashes on last iteration
for (int i = 0; i < array.Length; i++) → correct (< not <=)
Modifying a list while iterating with foreach: foreach (var x in list) { list.Remove(x); } → InvalidOperationException
for (int i = list.Count - 1; i >= 0; i--) { list.RemoveAt(i); }
🗺️ Maps SDK Connection

Loops appear everywhere in Maps SDK work: iterating through query results (FeatureQueryResult contains an IEnumerable), processing all graphics in a GraphicsOverlay, looping through layers in a map to toggle visibility, and processing offline map areas. The foreach loop is by far the most used pattern.

Functions & Methods

~50 min
Real-world analogy: A method is like a vending machine. You give it input (money + selection), it does its job internally, and gives you back output (your snack). You don't need to know how the internal heating element works — you just call it with the right inputs.

🧠 What is a method?

A method is a named, reusable block of code that performs a specific task. In C#, every method belongs to a class. Methods help avoid code repetition (DRY — Don't Repeat Yourself), organize logic into readable chunks, and make code testable and maintainable.

Structure: returnType MethodName(parameters) { body }

C#methods.cs
// ── METHOD ANATOMY ────────────────────────────────────────────
//   access  return   name          parameters
public static double CalculateDistance(double lat1, double lon1,
                                       double lat2, double lon2)
{
    // Haversine formula approximation
    double dLat = (lat2 - lat1) * Math.PI / 180;
    double dLon = (lon2 - lon1) * Math.PI / 180;
    return Math.Sqrt(dLat * dLat + dLon * dLon) * 111.0; // km
}

// Calling a method
double km = CalculateDistance(34.05, -118.24, 40.71, -74.00);

// ── VOID METHODS — do work, return nothing ────────────────────
public static void PrintLayerInfo(string name, bool isVisible)
{
    string status = isVisible ? "visible" : "hidden";
    Console.WriteLine($"Layer '{name}' is {status}");
}
PrintLayerInfo("Roads", true);  // "Layer 'Roads' is visible"

// ── OPTIONAL PARAMETERS (default values) ──────────────────────
public static string FormatCoords(double lat, double lon, int decimals = 4)
{
    return $"{lat.ToString($"F{decimals}")}, {lon.ToString($"F{decimals}")}";
}

FormatCoords(34.0522, -118.2437);        // uses default: 4 decimals
FormatCoords(34.0522, -118.2437, 2);     // 2 decimals

// ── NAMED ARGUMENTS ───────────────────────────────────────────
FormatCoords(lat: 34.0522, lon: -118.2437, decimals: 6);

// ── OUT PARAMETERS — return multiple values ────────────────────
public static bool TryParseCoordinates(string input,
    out double latitude, out double longitude)
{
    latitude = longitude = 0;
    string[] parts = input.Split(',');
    if (parts.Length != 2) return false;
    return double.TryParse(parts[0], out latitude)
        && double.TryParse(parts[1], out longitude);
}

// ── OVERLOADING — same name, different signatures ─────────────
public static void Log(string message) { ... }
public static void Log(string message, string level) { ... }
public static void Log(Exception ex) { ... }

// ── LAMBDA EXPRESSIONS — inline anonymous functions ───────────
// Used extensively with LINQ and event handlers
Func<double, double, double> addCoords = (a, b) => a + b;
Action<string> printLayer = name => Console.WriteLine(name);
Predicate<int> isValidZoom = z => z >= 1 && z <= 20;

📖 Access Modifiers Explained

  • public — accessible from anywhere in the application
  • private — only accessible within the same class (default for members)
  • protected — accessible within the class and its subclasses
  • internal — accessible within the same project/assembly
  • static — belongs to the class itself, not to an instance

⚠️ Common Mistakes

Forgetting to use the return value: CalculateDistance(lat1, lon1, lat2, lon2); // value discarded!
double dist = CalculateDistance(lat1, lon1, lat2, lon2);
Method doing too many things (poor design): LoadMapAndDrawPinsAndSaveToDatabase() → hard to test/maintain
LoadMap() + DrawPins() + SaveFeatures() → one job each
🗺️ Maps SDK Connection

The Maps SDK is built entirely on methods: MapView.SetViewpointAsync(), FeatureLayer.SelectFeaturesAsync(), GeometryEngine.Buffer(). Understanding parameters, return types, and especially methods that return Task (async methods) is essential before diving into the SDK.

Classes & Objects (OOP)

~60 min
Real-world analogy: A class is a blueprint for a house. You can build many houses (objects) from one blueprint. Each house has the same structure (properties: bedrooms, bathrooms) and can do the same things (methods: openDoor, lockWindow), but each house has different actual values (3 bedrooms vs 4 bedrooms).

🧠 The 4 Pillars of OOP in C#

  • Encapsulation — bundling data + behavior, hiding internal details
  • Inheritance — child class inherits from parent class (code reuse)
  • Polymorphism — one interface, many implementations
  • Abstraction — exposing only what's necessary, hiding complexity
C#classes_and_objects.cs
// ── DEFINING A CLASS ──────────────────────────────────────────
public class MapLayer
{
    // Properties — auto-implemented (compiler creates backing field)
    public string Name { get; set; }
    public bool IsVisible { get; set; } = true;   // default true
    public double Opacity { get; private set; } = 1.0; // read-only outside
    public static int TotalCreated { get; private set; } = 0; // shared

    // Constructor — called when creating a new instance
    public MapLayer(string name)
    {
        Name = name;
        TotalCreated++;
    }

    // Overloaded constructor
    public MapLayer(string name, double opacity) : this(name)
    {
        Opacity = Math.Clamp(opacity, 0.0, 1.0);
    }

    // Methods
    public void Toggle() => IsVisible = !IsVisible;

    public void SetOpacity(double value)
    {
        if (value < 0 || value > 1)
            throw new ArgumentOutOfRangeException(nameof(value));
        Opacity = value;
    }

    // ToString override — controls string representation
    public override string ToString()
        => $"[{Name}] visible={IsVisible}, opacity={Opacity:P0}";
}

// ── CREATING INSTANCES ────────────────────────────────────────
var roads = new MapLayer("Roads");
var parks = new MapLayer("Parks", 0.8);

roads.Toggle();                   // IsVisible = false
parks.SetOpacity(0.5);
Console.WriteLine(MapLayer.TotalCreated); // 2 (static)

// ── INHERITANCE ───────────────────────────────────────────────
public class FeatureLayer : MapLayer   // FeatureLayer IS-A MapLayer
{
    public string ServiceUrl { get; set; }

    public FeatureLayer(string name, string url) : base(name)
    {
        ServiceUrl = url;
    }

    // Override parent method
    public override string ToString()
        => $"{base.ToString()} url={ServiceUrl}";
}

// ── INTERFACES — define a contract without implementation ──────
public interface ILoadable
{
    Task LoadAsync();
    bool IsLoaded { get; }
}

public class ServiceLayer : MapLayer, ILoadable
{
    public bool IsLoaded { get; private set; }
    public async Task LoadAsync() { await Task.Delay(100); IsLoaded = true; }
    public ServiceLayer(string n) : base(n) {}
}

// ── RECORDS — immutable data objects (C# 9+) ─────────────────
public record MapPoint(double Latitude, double Longitude);

var la = new MapPoint(34.0522, -118.2437);
var ny = la with { Latitude = 40.7128, Longitude = -74.0060 };

⚠️ Common Mistakes

Forgetting 'new' when creating an instance: MapLayer layer = MapLayer("Roads"); → won't compile
MapLayer layer = new MapLayer("Roads");
Accessing instance members on a null reference: MapLayer layer = null; layer.Toggle(); → NullReferenceException
layer?.Toggle(); → safe null-conditional call
Confusing class (blueprint) with object (instance): MapLayer.Toggle(); → can't call instance method on the class
roads.Toggle(); → call on an instance
🗺️ Maps SDK Connection

The entire Maps SDK is built on OOP. Map, MapView, FeatureLayer, Graphic, Symbol, Renderer — all are classes. ILoadable is a real SDK interface you'll use constantly. Understanding inheritance explains why FeatureLayer has all the same properties as Layer plus extras. The GeoElement base class is why you can treat features and graphics the same way.

Error Handling — try / catch / finally

~40 min
Real-world analogy: Error handling is like a safety net under a tightrope walker. You hope you don't need it, but it's there if something goes wrong — and it lets you recover gracefully instead of crashing to the floor. The finally block is like the cleanup crew that sweeps up regardless.

🧠 What is an Exception?

An exception is an object that represents an error that occurred during execution. When code throws an exception, normal execution stops and C# looks for a catch block to handle it. Unhandled exceptions crash the program.

Common exceptions: NullReferenceException, ArgumentException, IndexOutOfRangeException, HttpRequestException, IOException.

C#error_handling.cs
// ── BASIC TRY/CATCH/FINALLY ───────────────────────────────────
try
{
    // Code that might fail goes here
    string content = File.ReadAllText("config.json");
    Console.WriteLine("File loaded!");
}
catch (FileNotFoundException ex)
{
    // Specific exception — handles only missing files
    Console.WriteLine($"Config file not found: {ex.Message}");
}
catch (UnauthorizedAccessException)
{
    // Another specific exception — no variable needed
    Console.WriteLine("No permission to read the file");
}
catch (Exception ex)
{
    // Catch-all — catches any exception not caught above
    Console.WriteLine($"Unexpected error: {ex.Message}");
    Console.WriteLine(ex.StackTrace);  // shows where it happened
}
finally
{
    // ALWAYS runs — even if exception occurred or was re-thrown
    // Use for cleanup: close files, release resources, log
    Console.WriteLine("Cleanup complete");
}

// ── THROWING EXCEPTIONS ───────────────────────────────────────
public static double ValidateZoom(double zoom)
{
    if (zoom < 0 || zoom > 23)
        throw new ArgumentOutOfRangeException(nameof(zoom),
            $"Zoom must be 0–23, got: {zoom}");
    return zoom;
}

// ── CUSTOM EXCEPTIONS ─────────────────────────────────────────
public class MapServiceException : Exception
{
    public int StatusCode { get; }

    public MapServiceException(string message, int statusCode)
        : base(message)
    {
        StatusCode = statusCode;
    }
}

// Usage
throw new MapServiceException("Service unavailable", 503);

// ── USING STATEMENT — auto-disposes resources ─────────────────
// Even if an exception occurs, the file is closed properly
using var reader = new StreamReader("data.csv");
string line = reader.ReadLine();
// reader automatically closed here when it goes out of scope

// ── NULL GUARD PATTERN ────────────────────────────────────────
public void AddLayer(MapLayer layer)
{
    // Guard clauses — fail fast and clearly
    ArgumentNullException.ThrowIfNull(layer);  // C# 10+ shorthand

    // Or manually:
    if (layer == null) throw new ArgumentNullException(nameof(layer));

    // Now safe to use layer
}

// ── EXCEPTION FILTERS ─────────────────────────────────────────
catch (HttpRequestException ex) when (ex.StatusCode == HttpStatusCode.Unauthorized)
{
    Console.WriteLine("401 — invalid API key");
}
catch (HttpRequestException ex) when (ex.StatusCode == HttpStatusCode.NotFound)
{
    Console.WriteLine("404 — service URL not found");
}

⚠️ Common Mistakes

Catching Exception and doing nothing (swallowing errors): catch (Exception) { } → hides bugs, impossible to debug
catch (Exception ex) { logger.LogError(ex); throw; } → log then re-throw
Catching base Exception when a specific one is better: catch (Exception ex) when loading a file → too broad
catch (FileNotFoundException ex) → specific and clear
Using exceptions for normal control flow: try { int.Parse(input); } catch { /* not a number */ } → expensive
int.TryParse(input, out int val) → designed for this
🗺️ Maps SDK Connection

Maps SDK operations can fail for many reasons: network outages, invalid API keys, malformed geometry, expired OAuth tokens. You'll wrap LoadAsync() calls in try/catch, handle ArcGISRuntimeException, and use finally to hide loading spinners whether or not an operation succeeded. The SDK also uses TaskCanceledException for cancelled async operations.

Asynchronous Programming — async / await

~70 min
Real-world analogy: Imagine ordering food at a restaurant. You don't stand frozen at the counter waiting for your food (synchronous). Instead, you take a number, sit down, talk to friends, check your phone — then the waiter brings your food when it's ready (asynchronous). Your time isn't wasted waiting.

🧠 Why async matters — especially for Maps SDK

Network calls, file I/O, and database queries all take time. If you make these calls synchronously on the UI thread, your app freezes — the map stops rendering, buttons don't respond, users think it crashed. async/await lets you start a long operation, immediately free the thread to do other work, then resume when the result arrives.

The Maps SDK uses async everywhere: loading layers, running queries, geocoding addresses, downloading offline maps — all return Task or Task<T>.

C#async_fundamentals.cs
// ── THE TASK TYPE ─────────────────────────────────────────────
// Task       — represents an async operation with no return value
// Task<T>   — represents an async operation that returns type T

// ── ASYNC METHOD SYNTAX ───────────────────────────────────────
public async Task<string> FetchMapConfigAsync(string url)
{
    using var client = new HttpClient();

    // 'await' means: "start this, don't block, resume when done"
    string json = await client.GetStringAsync(url);

    return json;  // Task<string> automatically wraps this
}

// ── VOID ASYNC — use only for event handlers! ─────────────────
private async void LoadMapButton_Click(object sender, EventArgs e)
{
    // Event handlers MUST be void — can't await them
    await LoadMapAsync();
}

// For everything else: async Task, never async void
public async Task LoadMapAsync()
{
    // Sequential awaits — waits for each one before continuing
    await AuthenticateAsync();
    await LoadBaseLayersAsync();
    await LoadFeatureLayersAsync();
}

// ── PARALLEL EXECUTION with Task.WhenAll ──────────────────────
public async Task LoadAllLayersAsync()
{
    // These run SIMULTANEOUSLY — much faster than sequential!
    Task roadsTask    = LoadLayerAsync("Roads");
    Task buildTask   = LoadLayerAsync("Buildings");
    Task parksTask   = LoadLayerAsync("Parks");

    await Task.WhenAll(roadsTask, buildTask, parksTask);
    // Continues only after ALL three are done
}

// ── CANCELLATION — let users cancel long operations ───────────
public async Task<List<Feature>> QueryFeaturesAsync(
    QueryParameters query,
    CancellationToken cancellationToken = default)
{
    // Check if cancelled before heavy work
    cancellationToken.ThrowIfCancellationRequested();

    var results = await featureLayer
        .QueryFeaturesAsync(query, cancellationToken);

    return results.ToList();
}

// Using cancellation from the UI
CancellationTokenSource cts = new();
var features = await QueryFeaturesAsync(query, cts.Token);
cts.Cancel();  // called when user clicks 'Cancel'

// ── ASYNC WITH ERROR HANDLING ─────────────────────────────────
public async Task SafeLoadAsync()
{
    try
    {
        var map = await LoadMapAsync();
    }
    catch (TaskCanceledException)
    {
        Console.WriteLine("User cancelled the operation");
    }
    catch (HttpRequestException ex)
    {
        Console.WriteLine($"Network error: {ex.Message}");
    }
    finally
    {
        HideLoadingSpinner();  // always hide spinner
    }
}

// ── REAL MAPS SDK PATTERN ─────────────────────────────────────
private async Task InitializeMapAsync()
{
    var map = new Map(BasemapStyle.ArcGISStreets);
    mapView.Map = map;

    var featureLayer = new FeatureLayer(new Uri("https://..."));
    map.OperationalLayers.Add(featureLayer);

    // LoadAsync() is awaited — don't forget the await!
    await featureLayer.LoadAsync();

    if (featureLayer.LoadStatus == LoadStatus.Loaded)
        Console.WriteLine("Layer ready!");
}

⚡ The Golden Rules of async/await

  • If you await something, your method must be async
  • Async methods should return Task or Task<T> (not void, except event handlers)
  • Never use .Result or .Wait() — this causes deadlocks in UI apps
  • Always await async methods — don't fire-and-forget
  • Method names should end in Async by convention
  • Async propagates upward — if you await inside, your method should be async too

⚠️ Common Mistakes

Using .Result or .Wait() — causes deadlocks in UI apps: var result = LoadMapAsync().Result; → DEADLOCK!
var result = await LoadMapAsync(); → correct
Forgetting await — gets Task, not the value: string json = client.GetStringAsync(url); → Type error! It's a Task
string json = await client.GetStringAsync(url);
Using async void outside event handlers (exceptions disappear!): public async void LoadData() { ... } → exceptions are lost
public async Task LoadDataAsync() { ... }
Sequential awaits when parallel is possible: await LoadRoads(); await LoadBuildings(); → takes 2x time
await Task.WhenAll(LoadRoads(), LoadBuildings()); → runs together
